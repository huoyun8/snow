## 七、2026-10-21 修复：右键重新进入屏幕选区界面

问题：按快捷键进入屏幕选区界面后按右键，界面没有真正退回"首次进入"的选框状态，
鼠标一动就被智能吸附成一个窗口大小的框（智能选取），用户无法重新自由框选。

改动：

| 文件 | 改动 |
|---|---|
| `Src/Win/WinCap.h` / `.cpp` | 新增 `WinCap::restartSelect()`：一次性把窗口退回首次进入的选区状态 —— 归零按下态、清选区、收起工具条并复位工具选中态、放大镜摆回光标处、把焦点抢回 WinCap。 |
| `Src/Win/WinCap.cpp` `onDown`（右键） | Select 阶段、Adjust 阶段（点在空白且未画过标注）右键都改走 `restartSelect()`，不再各写一份复位逻辑。 |
| `Src/Win/WinCap.cpp` `ensureAnnotation` | 工具条已存在但被 hide 过时重新 `show()`；修复"右键重选区 → 再框一次 → 标注工具条再也不出现"。 |
| `Src/Win/CutMask.h` / `.cpp` | `autoSnap` 语义明确为"智能吸附总开关"，同时管悬停吸附（`highlight`）与拖动吸附（`makeRect`）。`restartSelect()` 把它置为 `false`，右键后是纯手动十字选框，光标划过哪里就是哪里。 |

行为：

- 右键 = 重新开始一次框选，和刚按完快捷键那一帧一致（全屏、无选区、十字光标 + 放大镜、无工具条）。
- 右键后不再智能识别窗口，必须自己按住左键拖框。
- 想让右键后的状态和首次进入**完全一致**（保留悬停智能吸附），把 `WinCap::restartSelect()` 里的 `cutMask->autoSnap = false;` 改成 `true` 即可。
- 首次进入（快捷键）仍是原来的智能吸附，未改动。
- 已画过标注后右键点空白仍不会重开选区（保持原设计：标注开始后选框已结束）。


## 八、2026-10-21 第二轮：冗余清理 + 全面 bug 修复

本轮目标：清掉上一轮遗留的死代码 / 重复实现，并修掉通读全工程时发现的真实缺陷。

### 8.1 未初始化成员（会导致"画不出来"或乱飞）

| 文件 | 问题 | 修复 |
|---|---|---|
| `Src/Shape/ShapeBase.h` | `bool isUndo;` **没有初值**。除了 `History::undo/redo`，全工程没人给它赋过值，而 `WinCap::layout` / `WinPin::layout` 的绘制循环第一句就是 `if (!curve->isUndo)`。未初始化内存是随机值，新建标注可能整个不显示，或者撤销一次后再也回不来 | 改为 `bool isUndo{ false };`，`draggerSize` 同时给出默认值 `6.f` |
| `Src/Shape/ShapeRect.h` | `float strokeWidth, pressX, pressY;` 三个都没有初值（`ShapeEllipse` 同一组成员是有初值的）。在第一次 `mouseDown` 之前若先来一次 `mouseDrag` / `mouseWheel`，`std::minmax(pressX, x)` 就是拿垃圾值算矩形 | 三个都补 `{ 1.f }` / `{ 0.f }`，与 `ShapeEllipse` 对齐 |

### 8.2 空指针路径

| 文件 | 问题 | 修复 |
|---|---|---|
| `Src/Shape/ShapeArrow.cpp` `makeArrow` | `CreatePathGeometry` 失败（设备丢失 / 显存吃紧）时 `path` 是空的，紧接着无条件 `path->Open()` → 崩溃 | 加 `if (!path) return;`，`paint` 与 `mouseMove` 里本来就有 `!path` 守卫，画面只是这一帧没有箭头 |
| `Src/Shape/ShapeLine.cpp` `makePath` | 同上，`CreatePathGeometry` 后直接 `path->Open()` | 同上，加 `if (!path) return;` |

### 8.3 逻辑错误

| 文件 | 问题 | 修复 |
|---|---|---|
| `Src/Shape/ShapeArrow.cpp` `mouseMove` | 命中判定只用 `FillContainsPoint`。空心箭头画的是描边（`DrawGeometry`），但命中判定的是填充区域 —— 点在轮廓内部（视觉上是空的）反而算命中，点真描边上却常常拖不起来 | 按 `isFill` 分流：实心用 `FillContainsPoint`，空心用 `StrokeContainsPoint`（判定宽度放宽到 3 倍 dpi，否则 1px 描边几乎点不中） |
| `Src/Shape/ShapeNumber.cpp` `mouseWheel` | 自己写了一个 `r <= 6.f * win->dpi` 的下限判断，与 `ToolSub` 里滑块值域表的 `min = 6`（**逻辑**像素）重复且不等价：150% 缩放下 `6*dpi = 9`，半径到 9 就被拦下，滚不到值域真正允许的 6 逻辑像素 | 删掉这段判断，下限完全交给 `setShapeSliderVal`；另加"夹完还是原值就直接返回"，不再每格都重建 path + textLayout + 整窗重绘 |
| `Src/Win/WinSettingShortcut.cpp` `onKeyUp` | 只按修饰键（Ctrl / Alt / Shift / Win）再松手时，`tempKeys` 里只有修饰键，`isValidShortcutKeys` 必然失败 → `endCapture()`。表现为"点了按钮、按了下 Ctrl 想取消，结果还得多点一次才能重新录制" | `onKeyUp` 里修饰键直接 `return`，不动捕获状态 |
| `Src/Win/WinSettingShortcut.cpp` `~WinSettingShortcut` | 三个 `event_token` 摘完没清空，析构后再被误 remove 会把 token 当有效值重放 | 摘完统一置 `{}`；新增 `VK_APPS`（菜单键）映射，避免它被当成未知键 |
| `Src/Update.cpp` `doCheck` | 第二个 `co_await client.GetBufferAsync(exeUrl)` 完全没有超时。网速慢或卡在半路时，这个协程一直挂着，连接和后台线程都收不回来 | 补一个 120 秒的超时 `dlGuard`，拿到结果立即 `Cancel` |
| `Src/Win/WinSetting.cpp` `onMenuItemClick` | `menus[menuIndex]` 不校验长度就解引用；`body->removeChild(content)` 会**销毁**子节点（`detachChild` 后 `unique_ptr` 析构），若三个分支都不命中，`content` 就是悬空指针，后面继续 `setFlexGrow` 等 | 加长度校验与 `oldItem` 空判；`content` 为空时直接返回 |
