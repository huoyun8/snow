# ScreenCapture 编译依赖说明

> 本文档说明编译本项目所需的全部依赖、来源、位置以及编译顺序。
> 适用于两种场景：① 本地 Windows + Visual Studio 编译；② GitHub Actions 云端自动编译（workflow 已内置编译逻辑，无需手动）。
>
> **注意：Ling / Yoga 已随仓库内置在项目根目录 `Ling/` 下，无需再从外部拉取。**

---

## 一、依赖总览

本项目编译需要 **1 个内置框架依赖** + **2 个系统级环境**：

| 类别 | 名称 | 来源 | 位置 | 用途 |
|---|---|---|---|---|
| 内置框架 | **Ling**（GUI 框架） | 已随仓库内置（原 `https://github.com/xland/Ling`） | 项目根目录 `Ling/` | 自研 C++ GUI 框架，本项目所有界面基于它 |
| 内置框架 | **Yoga**（布局引擎） | Ling 内置子目录 `Ling/yoga/` | `Ling/yoga` | Ling 依赖的 flex 布局库，需先编译出 `yoga.lib` |
| 系统环境 | **Visual Studio 2022**（C++ 桌面开发工具集 v145） | 微软官方安装器 | 默认安装 | 编译器 MSBuild/cl.exe |
| 系统环境 | **Windows 10/11 SDK** | VS2022 安装器自带 | 默认安装 | Windows API 头文件与系统库 |

## 二、依赖详解

### 2.1 Ling GUI 框架（必需，最关键）

- **位置（随仓库内置）**：`Ling/`
- **仓库结构**：
  ```
  Ling\
  ├─ Ling.vcxproj        # Ling 静态库工程
  ├─ Ling.slnx           # 解决方案（含 demo/Ling/yoga 三工程）
  ├─ include\            # Ling 头文件
  ├─ src\                # Ling 源码
  └─ yoga\               # Yoga 布局库（子工程）
     └─ yoga.vcxproj     # yoga 静态库工程
  ```
- **编译产出**：编译后生成 `Ling\x64\Release\Ling.lib`（静态库）

### 2.2 Yoga 布局引擎（Ling 强依赖，必须编译）

- **位置**：不单独拉取，包含在 `Ling/yoga`
- **原因**：本项目源码 `include\Node.h`、`WinBase.h` 直接 `#include <yoga/Yoga.h>`，所以 yoga 必须存在并编译。
- **编译产出**：生成 `Ling\x64\Release\yoga.lib`
- **大小写说明**：工程默认输出 `yoga.lib`（小写），项目链接时写 `Yoga.lib`（大写）。Windows 文件系统不区分大小写，`yoga.lib` 可正常匹配 `Yoga.lib`，无需改名。

## 三、本地 Windows 编译步骤（手动）

### 3.1 准备工作

1. 安装 **Visual Studio 2022**，勾选"使用 C++ 的桌面开发"（含 v145 工具集 + Windows SDK）。
2. 无需拉取 Ling，仓库已内置 `Ling/` 目录。
3. 确认目录：`Ling\yoga\yoga.vcxproj` 与 `Ling\Ling.vcxproj` 存在。

### 3.2 编译顺序（必须按此顺序）

> 先编 yoga → 再编 Ling → 最后编 ScreenCapture。**顺序不能乱**，因为 ScreenCapture 和 Ling 都依赖 Yoga.lib。

打开 **"x64 Native Tools Command Prompt for VS 2022"**，依次执行：

```bat
:: 第 1 步：编译 yoga.lib
msbuild Ling\yoga\yoga.vcxproj /p:Configuration=Release /p:Platform=x64 /p:SolutionDir=Ling\

:: 第 2 步：编译 Ling.lib
msbuild Ling\Ling.vcxproj /p:Configuration=Release /p:Platform=x64 /p:SolutionDir=Ling\

:: 第 3 步：编译 ScreenCapture.exe
msbuild Src\ScreenCapture.vcxproj /p:Configuration=Release /p:Platform=x64
```

### 3.3 产物位置

编译成功后：
- 依赖库：`D:\project\Ling\x64\Release\Ling.lib`、`D:\project\Ling\x64\Release\yoga.lib`
- 最终 exe：`Src\x64\Release\ScreenCapture.exe`

## 四、GitHub Actions 云端编译（推荐，全自动）

仓库内已预置 `.github/workflows/build.yml`，推送代码到仓库 main 分支即自动触发。**云端已自动完成编译，无需手动。Ling 已随仓库内置，无需拉取。**

workflow 自动执行的步骤（与本地一致）：

| 步骤 | 动作 | 说明 |
|---|---|---|
| 1 | `actions/checkout@v4` | 检出本仓库源码（含内置的 Ling） |
| 2 | `microsoft/setup-msbuild@v2` | 自动配置 MSBuild / VS 环境 |
| 3 | `msbuild yoga.vcxproj` | 编译 yoga.lib → `Ling\x64\Release\yoga.lib` |
| 4 | `msbuild Ling.vcxproj` | 编译 Ling.lib → `Ling\x64\Release\Ling.lib` |
| 5 | `msbuild ScreenCapture.vcxproj` | 编译 exe → `Src\x64\Release\ScreenCapture.exe` |
| 6 | `actions/upload-artifact@v4` | 上传 exe 作为构建产物，在 Actions 页面下载 |

**触发方式**：① push 到 `main` 分支自动触发；② 或在仓库 Actions 页面手动点 "Run workflow"。

## 五、vcxproj 依赖引用对照表（若手动改工程请勿破坏）

以下路径已写在 `Src/ScreenCapture.vcxproj`（Release|x64 与 Debug|x64 相同），改动会破坏编译。**Ling 已内置，故使用相对路径 `..\Ling`（相对 Src 目录）：**

| 项目 | 值 |
|---|---|
| AdditionalIncludeDirectories | `..\Ling;$(ProjectDir);` |
| AdditionalLibraryDirectories | `..\Ling\x64\$(Configuration);` |
| AdditionalDependencies | `dwmapi.lib;windowsapp.lib;comctl32.lib;imm32.lib;version.lib;ntdll.lib;Userenv.lib;Yoga.lib;Ling.lib;` |

> 注意：`Yoga.lib` / `Ling.lib` 就是第 3.2 步编译出的两个静态库；其余 `dwmapi`/`windowsapp`/`comctl32`/`imm32`/`version`/`ntdll`/`Userenv` 均为 **Windows 系统自带库**，随 Windows SDK 提供，无需额外安装。

## 六、常见问题

| 问题 | 解决 |
|---|---|
| 报错找不到 `Ling.h` / `yoga/Yoga.h` | 确认 `Ling/` 目录在仓库根目录，且未删除。若缺失可从 `https://github.com/xland/Ling` 恢复后放回 `Ling/` |
| 报错找不到 `Ling.lib` / `Yoga.lib` | 未先编译 Ling / yoga，按 3.2 顺序先编依赖 |
| 报错 v145 工具集 / Windows SDK | VS2022 未装"使用 C++ 的桌面开发"，补装 |
| Actions 编译失败 | 看 Actions 日志，多为路径或库顺序问题，对照本表排查 |
